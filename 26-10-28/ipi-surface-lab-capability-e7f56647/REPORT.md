# IPI Surface Lab：测试结论

测试日期：2026-10-28。真机：e7f56647（Xiaomi 23117RK66C，Android 16 / API 36）。当前安装版本：0.1.2。

## 总结

在已授予对应权限的条件下，普通第三方 APK 确实可以创建联系人、发布和更新自己的通知、写入日历事件、生成文件。自建测试联系人的姓名和备注可连续修改，重启 App 后仍可修改，不必逐次重新授权。

闹钟在本次实现中经过 HyperOS 启动确认和系统保存确认。手机原有联系人号码的修改、新版号码入口的真机写入，以及真机 Assist 隐藏数据交付，尚未完成实测，不能写成已验证。

## 关于“一次授权之后能不能继续改”

真机测试开始时，通讯录读写、日历读写、通知权限已经授权。本轮沿用这些授权，未用 ADB 代为授予权限。

v0.1.1 对同一测试联系人做了“修改 A → 重启 App → 修改 B → 恢复原值”，三次更新和独立查询均成功，联系人 ID 没变，没有再次请求系统授权。因此支持的结论是：**权限仍有效时，本机可以连续修改此类可写联系人，无需逐次确认**。不等于永久授权，也不推广到所有账户和只读联系人。

v0.1.2 新增通过系统选择器选择已有号码的独立入口，不再要求选中号码来自 App 自建登记；只更新选中的号码，可恢复选择时的原值。外部修改或版本冲突会阻止覆盖。该入口的号码修改与恢复已通过模拟器测试，真机仅验证安装、启动和入口显示。

## 验证范围

- 系统数据的写入与查询由本 App 的普通 Android API 执行；ADB 用于安装、UI 操作和读取 App 自己的日志，没有高权限代写系统数据。
- v0.1.2 的 18 项模拟器仪器测试、4 项单元测试及构建通过；不能把这些数字当作 18 项真机验证。
- 没有测试 Gemini、PICO 等助手的读取、指令采纳或工具执行。

## 测试结束时的数据状态

原有 14 个登记对象及旧日志未改变。自建联系人 209 的字段已恢复；测试闹钟已从系统时钟删除，没有启动新的计时器。

测试结束时保留了联系人 209、通知 1008/1009/1010、日程 12、三个文件和一个 Assist 页面配置，便于人工查看。电脑上的本轮清理不操作手机数据。
