# 另一台电脑复现实验

## 1. 获取完整仓库

```sh
gh auth login
gh repo clone ling-research-sec/IPI-screen-sec-vault
cd IPI-screen-sec-vault
```

仓库包含现有实验素材、结果、证据、过程归档和 Git 历史，无需 Git LFS。历史 ZIP 与展开内容可能重复，均保留。不要解压覆盖正式证据。

## 2. 环境

- 建议 macOS / Linux；Windows 使用 WSL 并另行验证 USB/ADB 接入。
- 安装 Python 3（本流程仅使用标准库）和 Android SDK Platform-Tools，使 `python3`、`adb` 可用。
- 使用有 USB 调试授权的实验手机。先运行 `adb devices`，把当前序列号写入本机配置。
- 生成 XLSX 另需 Codex 的 Node 和 `@oai/artifact-tool`。在另一台电脑的 Codex 中调用 `load_workspace_dependencies` 获取该机器路径；不复制本机 node_modules 或绝对路径。
- 原始适配为 Perplexity 默认助手，versionCode 260665、中文 UI、1080×2400、LineageOS 图库。App 版本、默认助手、分辨率或图库有变化时，先适配，不能直接宣称复现成功。

## 3. 工具及离线验证

可直接使用仓库内工具，无需安装 Skill：

```sh
python3 tools/android-screen-readability/scripts/test_pipeline.py
```

需要在 Codex 使用该 Skill 时，把 `tools/android-screen-readability` 复制到另一台电脑的 `~/.codex/skills/`；若已有同名目录，先备份，不覆盖自定义版本。

工具完整协议见 `tools/android-screen-readability/references/protocol.md`，起点配置见 `references/example-config.json`。图片生成器位于 Skill 的 `assets/`。

## 4. 复现实验步骤

1. 先阅读目标实验目录的 `实验说明.md`、正式逐轮证据与归档配置。实验一和实验二不是同一套字号、素材和扫档组合。
2. 复制示例配置到新的本地工作目录；按目标轮次设置素材、参考文本、Prompt、参数档位和 UI。旧归档保留原始绝对路径，只用于溯源；不要直接复用这些路径。
3. 把素材 PNG 原文件导入手机并核对哈希；不要把答案文本放到手机。新采集使用新的实验输出目录，不能覆盖已有轮次。
4. 按顺序执行下列命令，将占位路径换为本机真实绝对路径：

```sh
S="$PWD/tools/android-screen-readability"
C="/ABS/LOCAL/config.json"
python3 "$S/scripts/pipeline.py" plan "$C"
python3 "$S/scripts/pipeline.py" preflight "$C"
# 核对设备、素材、亮度和协议后，明确开始新一轮采集：
python3 "$S/scripts/pipeline.py" run "$C" --execute
python3 "$S/scripts/pipeline.py" score "$C"
# NODE / MODULES 使用另一台电脑 load_workspace_dependencies 的真实返回值
python3 "$S/scripts/pipeline.py" report "$C" --execute --node "$NODE" --node-modules "$MODULES"
python3 "$S/scripts/pipeline.py" verify "$C"
```

历史记录用于重放与审计，不等于新手机端到端验证。App 服务端变化也可能影响结果。中断后先检查状态，不要盲目重发。

## 5. 两台电脑协作

每次开始前执行 `git pull --ff-only`，结束后提交并 `git push`。避免两台电脑同时改同一份 XLSX；可各自使用不同轮次或分支。

上传保留了过程归档；仅排除系统元数据、Office 锁文件、Python 缓存、node_modules，以及一条指向仓库已有目录的本机绝对别名。
